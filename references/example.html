superspec 技术规格书

目标与边界

在深入具体流程前，先对齐 superspec 的边界：它解决什么问题、明确不做什么、职责停在哪里。

核心目标

  • 把资深架构师写技术方案的隐性经验显性化，引导 LLM 自上而下地解构一个功能的业务生命周期。
  • 产出人类优先、AI 无歧义的规格：人能在 30 秒内抓住边界、凭直觉建立心智模型，AI 能拿到逐条可执行的硬约束。
  • 以单文件自包含 HTML 交付，双击即读，零构建、零外部依赖。

非目标

  • 不写具体实现——不产出源码、伪代码或大段 Schema。
  • 不做 QA 验收标准与测试用例。
  • 不做项目管理、排期或工时估算。
  • 不替代人工技术评审；主线是否成立由人拍板，LLM 不代为决策。
  • 不在 Coding 阶段自动回写规格（Living Spec 的修改主权在人）。

职责边界

  • 管辖：从「功能意图输入」到「规格归档 + Preview 交付」这一段的方法与排版。
  • 排除：Coding 执行、CI/CD、运行时监控与一切跨项目基建。

整体工作流程

superspec 把「写技术方案」本身视作一条单向推导的流水线。从接收功能意图出发，到交付一份可归档的规格书终止，中间经过八个阶段。流程严格单向推进：每一项校验都嵌套在它发生的阶段内，不事后补漏。

人机协作直觉

假设 superspec 已上线。你只丢给它一句话：「给 X 功能写份技术方案」。它不会立刻甩出一篇长文，而是先还你一张解剖草案——这个功能分几个阶段、每阶段做什么、哪里必须拦、哪里可以降级。你扫一眼，说「第二、三阶段合并」「这里没有降级，直接阻断」。确认之后，它才把整条生命线逐段写透，在你编辑器右侧展开成规格书。出问题时，你看到的不是一堆报错，而是一句明确的定位：「卡在草案对齐门禁——你还没确认主线」。边界与主线的决定权始终在你手里，它负责把骨架摊开、把细节写实。

阶段详解

以下详细展开八个阶段的执行逻辑。每个阶段明确四个维度：接收什么、机制与动作、阻断与降级条件、向下游交付什么。

意图接入（Intake）

把一句模糊的功能意图，收敛成可处理的结构化输入。

输入
一句或一段功能意图描述，可附背景链接。
机制
识别功能主体、触发源与期望产物，不做任何方案展开。
阻断/降级
阻断：意图为空或指代不明、无法定位功能主体时，停下索要澄清。降级：背景不全但主体可辨，带「背景待补」标记继续。
产出
功能主体、输入源、期望产物三要素，进入边界划定。

边界划定（Scoping）

在动手之前，先把「做什么、不做什么」锁定为可读共识。

输入
意图接入阶段的三要素。
机制
推导 Goals、Non-Goals 与 Boundaries。Non-Goals 取「本可合理成为目标、但本次明确不做」的事项，而非简单的否定句。
阻断/降级
阻断：边界与既有功能冲突，或管辖越界到无关基建。降级：Non-Goals 不完整，标记待补。
产出
置顶的 Scope & Non-Goals 面板内容。

时序推导（Lifecycle Discovery）

沿着真实数据流向，推出一条自上而下的单向生命线。

输入
已对齐的边界共识。
机制
按数据流向推导主线（接入→提取→准入→门禁→装配→补全→交互→持久化），并按功能复杂度合并或拆解阶段。
阻断/降级
阻断：出现时间倒流、环路依赖，或无法定位数据流向。降级：某阶段职责模糊，标记「待对齐」。
产出
端到端单向生命周期主线草案。

草案对齐门禁（Alignment Gate）

整条流水线里唯一的人工决策点，未经确认不得继续。

输入
生命周期主线草案。
机制
把草案呈给你，确认阶段划分与阻断/降级分布是否符合真实业务，由你增删合并节点。
阻断/降级
阻断（Fail-Closed）：你确认之前，严禁进入全文展开。此处没有降级——未对齐的主线不允许流向下游。
产出
经确认的生命周期主线，冻结为写作基准。

双层表达（Elaboration）

先建立直觉，再落下约束，把主线写成完整正文。

输入
已确认的主线。
机制
先写 Guide-level 使用者叙述建立直觉，再按 Reference-level 逐阶段写清输入、机制、阻断降级与状态迁移；契约只描述核心字段及其判定角色，不贴代码。
阻断/降级
阻断：机制无法落到可验证的规则。降级：个别字段语义待补，显式标记。
产出
完整正文（直觉层 + 约束层）。

红线自检（Compliance Check）

对照写作红线逐条自检，并收敛出全局产物。

输入
完整正文。
机制
逐条核对：无 PM 公文、无代码堆砌、无孤立规则碎片、无跨域污染；同时收敛全局不变量与排障字典。
阻断/降级
阻断：命中任一红线，回退到双层表达阶段重写对应段落。
产出
合规正文 + 全局不变量 + 排障字典。

排版装配（Composition）

把合规正文装配成一份可独立打开的单文件规格。

输入
合规正文。
机制
套用 Kami 视觉体系，装配导航、边界面板、阶段四元组与流程，输出零依赖的单文件 HTML。
阻断/降级
阻断：引入外部依赖，或破坏单文件自包含。
产出
spec.html 成品。

归档交付（Delivery）

落盘并挂载预览，把规格的后续主权移交给人。

输入
spec.html 成品。
机制
写入 features/<feature>/technical-design.html，挂载右侧 Preview 并关闭画中画。
阻断/降级
降级：Preview 挂载失败时保留文件，并提示手动打开。
产出
可归档、可预览的 Living Spec。

核心原则

以下原则在任何阶段都必须恒成立，是判断一份规格是否合格的底线。

  • 时序主权：阅读顺序严格沿时间箭头前进，校验与错误码嵌于发生节点，禁止孤立罗列与时间倒流。
  • 人类优先：边界共识与使用直觉先于硬约束呈现，机器可解析性不得牺牲人类阅读直觉。
  • 对齐前置：未经草案对齐门禁确认的主线，不得进入全文展开。
  • 自包含：交付物零构建、不依赖外部资源，但允许项目内相对链接互联成层级；Feature 方案不混入无关基建。
  • 主权在人：规格仅在设计与讨论阶段被主动书写，Coding 期 agent 只能上报偏差，不得自动回写。

常见异常排查

当规格输出异常时，按下表定位它发生的阶段与处置方式。

异常表现定位阶段归属与处置
看不懂在做什么、边界含糊边界划定回补 Non-Goals 与 Boundaries 面板。
读到后面要翻回前面才能懂时序推导生命线时间倒流，重排为单向时序。
直接给出完整方案、未经确认草案对齐门禁跳过门禁，回退并先冻结主线。
通篇大词、无可验证机制表达 / 自检命中 PM 公文红线，重写为可验证规则。
粘贴了大段源码或 Schema表达 / 自检命中代码堆砌红线，改为描述字段判定角色。
错误码或规则被单独列成附录推导 / 自检规则碎片化，嵌回其发生的生命周期节点。
HTML 需联网或构建才能阅读排版装配破坏自包含，去除外部依赖。
Coding 后规格被自动改动交付 / 全局越权回写，应改为上报偏差提醒。
